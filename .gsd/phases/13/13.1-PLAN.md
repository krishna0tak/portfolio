# Plan 13.1: Fix Scroll Animation Load Performance (Vercel)

<objective>
The scroll animation preloads all 299 JPG frames eagerly before rendering anything. On Vercel (CDN-served, cold requests, no local cache), this forces users to wait for 299 HTTP requests to complete before the animation section becomes interactive.

Fix: progressive/lazy frame loading — show the first frame immediately, then batch-load remaining frames in the background. The canvas renders as soon as frame 0 is ready, and frame scrubbing only uses loaded frames (falling back to closest available).

Purpose: Eliminate the "Loading 3D Frame Sequence (N / 299)" blocking screen on Vercel deployments.
Output: Updated ScrollUnboxing.jsx with fast-start progressive loading.
</objective>

<context>
Load for context:
- src/components/ScrollUnboxing.jsx

<task type="auto">
  <name>Rewrite ScrollUnboxing with progressive frame loading</name>
  <files>src/components/ScrollUnboxing.jsx</files>
  <action>
    Replace the current eager preload-all-299 strategy with this progressive approach:

    1. **Immediately load frame 0 only** — use a single `new Image()` for `/frames/ezgif-frame-001.jpg`, mark component as "ready" the moment it loads (or on first `onload`). Set `isReady = true` as soon as frame 0 is available, so canvas shows immediately.

    2. **Batch-load remaining frames in the background** — after frame 0 loads, load frames 1-298 in batches of 20 using `requestIdleCallback` (fall back to `setTimeout(..., 0)` if not supported). Store each loaded image in a ref array `imagesRef.current[i]`.

    3. **Remove the blocking loading overlay** — remove the `!isLoaded` fullscreen spinner/blocker entirely. Replace with a subtle bottom-right progress indicator that appears only while background loading is in progress, and auto-hides when all frames are done.

    4. **Update drawFrame** — `drawFrame(index)` should find the nearest loaded frame if `imagesRef.current[index]` isn't loaded yet: scan backwards from `index` until a loaded image is found and draw that. This prevents blank canvas during scrubbing while frames are still loading.

    5. **Scroll handler** — remains the same passive scroll listener. It now calls `drawFrame` which gracefully handles missing frames.

    6. **State to keep:**
       - `isReady` (bool): true once frame 0 loaded → canvas is visible
       - `loadedCount` (number): tracks background loading progress
       - `allLoaded` (bool): true when all 299 loaded → hides progress indicator

    AVOID: Using `useState` for the images array — use `useRef` instead. Calling `setState` 299 times causes 299 re-renders and tanks performance. The images array must be a ref.
    AVOID: Removing the scroll scrubbing logic — only change the loading strategy.
    AVOID: Using `img.decode()` — simple `onload` is sufficient.

    Keep the canvas drawing logic (`drawFrame` with devicePixelRatio scaling, contain-fit logic) exactly as-is.
  </action>
